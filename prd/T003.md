# T003 — Notes, proposals, and consensus loops

## Metadata

- Last specification update: 2026-09-12

## Objective

Implement the non-canonical information loops that allow agents to deposit weak signals, reinterpret each other's findings, deliberate on canonical changes, and reach operational consensus without a manager agent.

## Scope

### In scope

- Markdown notes plus machine metadata;
- replies and consumption lineage;
- proposal artifacts in `reports/` plus machine metadata;
- proposal creation from notes;
- support, neutral, challenge, hard objection, resolution, amendment;
- consensus readiness calculation.

### Out of scope

- automatic canonical task materialization (T004);
- semantic evaluation of proposal quality.

## Contracts and interfaces

Notes are weak signals and remain `OPEN` until consumed by a task/report/proposal.

Proposal author never counts as a reviewer. Current stance is the latest stance per reviewer. Hard objections are separate blocking records and remain blocking until explicitly resolved by their author.

Default consensus threshold: >=3 non-author reviewers, >=2 current supporters, 0 unresolved hard objections.

## Sub-tasks

### T003-SUB001 — Implement notes and replies

- Goal: create searchable, attributable notes with replies and consumption status.
- Dependencies: —
- Acceptance criteria:
  - Note creation records author/time/type/task.
  - Replies preserve authorship.
  - Notes can be listed/search and marked consumed with lineage.
- Verification:
  - Automated tests in T005.

### T003-SUB002 — Implement proposal lifecycle

- Goal: create human-readable proposal artifacts and machine coordination metadata.
- Dependencies: T003-SUB001
- Acceptance criteria:
  - Proposals can originate from notes.
  - Support/neutral/challenge stances are attributable and latest-stance based.
  - Hard objections have stable IDs and explicit resolution.
  - Amendments preserve history.
- Verification:
  - Automated tests in T005.

### T003-SUB003 — Implement consensus readiness

- Goal: mechanically calculate whether formal consolidation conditions are satisfied.
- Dependencies: T003-SUB002
- Acceptance criteria:
  - Author excluded from reviewer/support counts.
  - Unresolved hard objection blocks readiness.
  - No semantic judgment is performed.
- Verification:
  - Automated tests in T005.

## Risks

- Notes can become a dumping ground if agents do not revisit unconsumed signals.
- Proposal proliferation can occur if agents fail to inspect semantically overlapping open proposals.

## Open questions

- Semantic duplicate detection intentionally deferred until pilot evidence exists.
