# T002 — Filesystem coordination and claims

## Metadata

- Last specification update: 2026-09-12

## Objective

Implement dependency-free Linux coordination primitives for a shared repository: root discovery, short `flock` critical sections, stable counters, event append, task-index parsing, claims, leases, heartbeat, release, and completion validation.

## Scope

### In scope

- Python 3.11+ standard library only;
- repo discovery from `PRD.md`;
- `.blackboard` initialization;
- atomic JSON writes;
- global short lock for metadata mutation;
- claim expiration and takeover;
- owner-only heartbeat/release;
- `bb status`, `bb available`, `bb claims`;
- `bb complete` as a validator/release operation, not a semantic decision.

### Out of scope

- notes/proposals;
- automatic source-file locks;
- background processes.

## Contracts and interfaces

`bb claim T003` creates `.blackboard/claims/T003.json` with actor, start time, and lease expiry.

A claim is valid only for an existing task and cannot be stolen before expiration.

`bb complete T003` succeeds only if both root `PRD.md` and `progress/PROGRESS-T003.md` already state `COMPLETE`; it then releases the owner claim and records the event.

## Sub-tasks

### T002-SUB001 — Implement repository primitives

- Goal: root discovery, atomic lock/write, counters, event append, task/progress parsing.
- Dependencies: —
- Acceptance criteria:
  - Mutations use Linux `fcntl.flock` for short critical sections.
  - Stable counters never decrement/reuse IDs.
- Verification:
  - Unit tests in T005.

### T002-SUB002 — Implement claim lifecycle

- Goal: exclusive task lease with expiry, heartbeat, release, and completion validation.
- Dependencies: T002-SUB001
- Acceptance criteria:
  - Concurrent valid claims cannot both succeed.
  - Expired claim can be taken over.
  - Non-owner cannot heartbeat/release a live claim.
- Verification:
  - Unit tests in T005.

### T002-SUB003 — Implement routing visibility

- Goal: status/available/claims commands expose the current coordination state.
- Dependencies: T002-SUB002
- Acceptance criteria:
  - Available tasks respect root status and completed dependencies.
  - Expired claims are not reported as live.
- Verification:
  - CLI smoke tests in T005.

## Risks

- Shared working tree remains a separate concurrency concern and is intentionally not solved by task claims.

## Open questions

- None blocking implementation.
