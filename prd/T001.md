# T001 — Collaboration contract and skill

## Metadata

- Last specification update: 2026-09-12

## Objective

Define the controller-free Blackboard collaboration contract and encode it as a portable `SKILL.md` compatible with heterogeneous agents.

## Scope

### In scope

- information layers and authority model;
- cold-start discovery loop;
- execution, review, note, proposal, blocker, and idle loops;
- claim semantics;
- consensus semantics;
- anti-chat and anti-transcript rules;
- Git/provenance behavior;
- clear separation between agent policy and `bb` mechanism.

### Out of scope

- actual CLI implementation;
- agent-framework-specific adapters;
- Telegram integration.

## Contracts and interfaces

The skill assumes a Scalable Ralph-style repository:

- `PRD.md` — global routing context;
- `prd/Txxx.md` — normative macro-task specification;
- `progress/PROGRESS-Txxx.md` — bounded hot execution state;
- `reports/` — cold evidence and proposal artifacts;
- Git — historical provenance.

The Blackboard extension adds:

- `.blackboard/claims/`;
- `.blackboard/notes/`;
- `.blackboard/proposals/` machine metadata;
- `.blackboard/events.jsonl`.

## Sub-tasks

### T001-SUB001 — Define information model

- Goal: define canonical, operational, deliberative, observational, and historical information layers.
- Dependencies: —
- Acceptance criteria:
  - Each layer has one clear responsibility and authority level.
  - Notes, reports, proposals, Progress, PRD, and events are explicitly distinguished.
- Verification:
  - Review `SKILL.md` sections "Information model" and "Authority".

### T001-SUB002 — Define agent loops

- Goal: encode the collaborative loops so agents repeatedly read and react to shared state rather than execute once.
- Dependencies: T001-SUB001
- Acceptance criteria:
  - Cold start, execution, discovery, notes, review, blocker, proposal, and idle loops are specified.
  - Agents are explicitly allowed to abstain.
- Verification:
  - Review `SKILL.md` loop sections.

### T001-SUB003 — Define policy/mechanism boundary

- Goal: ensure no intelligent controller is introduced.
- Dependencies: T001-SUB002
- Acceptance criteria:
  - `bb` is defined as mechanical only.
  - Semantic decisions remain distributed among agents.
- Verification:
  - Search `SKILL.md` for controller and decision rules.

## Risks

- Too much procedural detail may turn the skill into a rigid workflow rather than opportunistic Blackboard behavior.
- Too little structure may degrade into group chat or duplicate work.
